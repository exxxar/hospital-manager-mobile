# Clinic Staff Mobile — Android client

Android-клиент для системы управления персоналом медицинской клиники.
Проект: Kotlin, Jetpack Compose, Material 3, MVVM, Retrofit/OkHttp, Room,
DataStore Preferences, Coroutines/Flow.

## Возможности

- SERVER / DEMO режимы при запуске.
- DEMO работает без интернета, импортирует JSON в Room и читает данные из SQLite.
- SERVER: вход по email/паролю, Bearer token, профиль, сотрудники, отделения,
  расписание, выходные, уведомления, dashboard.
- Один интерфейс для обоих источников данных через `ClinicRepository`.
- Личный кабинет: ФИО, должность, email, телефоны, специализация и квалификация.\n- В DEMO можно переключать тестовые профили сотрудников; в SERVER показывается профиль авторизованного сотрудника.
- Поиск сотрудников, фильтр по типу, просмотр карточек.
- Только чтение кадровых данных. В DEMO доступен локальный сброс данных.
- GitHub Actions workflow для сборки debug APK.

## Открытие

1. Откройте каталог `android/` в Android Studio (Hedgehog или новее).
2. Установите Android SDK 35.
3. Дождитесь Gradle Sync.
4. В `android/app/build.gradle.kts` задайте `BuildConfig.API_BASE_URL`
   (по умолчанию `https://example.com/api/v1/`).
5. Запустите на Android 8.0+ (minSdk 26).

## Настройка сервера

`API_BASE_URL` должен оканчиваться на `/api/v1/`, например:
`https://clinic.example.ru/api/v1/`

Для локального эмулятора Android можно использовать:
`http://10.0.2.2:8000/api/v1/`
При HTTP разработка требует разрешить cleartext traffic в manifest;
для production используйте HTTPS.

Ожидаемые endpoints Laravel API:
- POST `auth/login` {email,password} -> {token,user}
- POST `auth/logout`
- GET `auth/me`
- GET `dashboard`
- GET `employees?search=&type=&department_id=&page=&per_page=`
- GET `employees/{id}`
- GET `departments`
- GET `departments/{id}`
- GET `schedules`
- GET `day-offs`
- GET `notifications`
- PATCH `notifications/{id}/read`

Все защищённые запросы используют `Authorization: Bearer <token>`.

## DEMO данные

Исходные JSON находятся в `app/src/main/assets/demo/`.
Первый запуск импортирует данные в Room. DEMO работает автономно.
Переход в другой режим не удаляет локальные данные.

## Сборка APK

Локально:
```bash
cd android
gradle assembleDebug  # при установленном Gradle 8.9
```
Windows:
```bat
gradle assembleDebug  # Windows, при установленном Gradle 8.9
```
APK: `android/app/build/outputs/apk/debug/app-debug.apk`

В GitHub Actions используется workflow `.github/workflows/android.yml`.
Для release-подписи добавьте keystore и пароли в GitHub Secrets; не храните
их в репозитории.

## Ограничения текущей интеграции

Это полный исходный проект клиента, но его нужно проверить на вашем сервере:
контракт JSON должен совпадать с API v1. В API Laravel уведомления будут
пустыми, пока серверная часть не начнёт создавать Laravel Notifications.
Реальные данные сотрудников должны фильтроваться и авторизовываться на сервере.

## Календарь расписания

Раздел «График» содержит месячный календарь с переходом между месяцами, выбором дня, маркерами смен и выходных, а также карточками событий выбранной даты. Поддерживаются точные даты и повторяющиеся записи по дню недели (русские и английские названия).

## Расширенный календарь персонала

Календарь поддерживает фильтр по сотруднику, отпуска, больничные и замены смен. DEMO-данные находятся в `assets/demo/absences.json` и `assets/demo/replacements.json`. Для SERVER-режима предусмотрены `GET /api/v1/absences` и `GET /api/v1/shift-replacements`. Мобильная часть работает в режиме чтения; кадровые изменения выполняются в основной системе.

## Главная панель и лента активности

Главная панель расширена сводкой по сотрудникам, отделениям, уведомлениям, отсутствиям и сменам на текущий день. Добавлены быстрые переходы к основным разделам, ближайшие смены и кадровые события. Раздел «Активность» формирует общую ленту из уведомлений, отпусков, больничных, выходных и замен смен, используя данные локальной базы и серверной синхронизации.

## Задачи и заявки

Добавлены разделы «Задачи» и «Заявки». DEMO-данные: `assets/demo/tasks.json` и `assets/demo/service_requests.json`. В демонстрационном режиме можно менять статус задачи и создавать локальные заявки; данные сохраняются в Room. Серверная синхронизация этих двух разделов ещё не подключена — см. API_CONTRACT.md.

## Laravel 7 SERVER-интеграция задач и заявок

Клиент теперь использует общий конверт API `{success,message,data}` для REST-ответов. В SERVER-режиме загружает задачи и заявки, отправляет PATCH статуса задачи и POST новой заявки; ответы сохраняются в Room. Для уведомлений идентификаторы переведены на строковый формат (UUID Laravel). Примените Laravel-патч из `clinic_laravel_mobile_api_patch.zip` и настройте `API_BASE_URL`.


## Администрирование и встроенная отладка

Добавлен раздел «Админ» для пользователей с ролью `admin`: создание задач, выбор исполнителя и срока, контроль статусов задач, обработка заявок (в работу / выполнена / отклонена). В DEMO-режиме можно переключиться на демо-профиль администратора Андрей (id=5).

Добавлен раздел «Отладка»: журнал приложения хранит последние 300 записей локально, фильтруется по INFO/WARN/ERROR/HTTP, позволяет копировать и очищать лог. Сетевой лог показывает HTTP-метод, путь, код ответа и время запроса. Тела запросов/ответов, пароли и Bearer-токены намеренно не записываются, чтобы не сохранять персональные и медицинские данные.

Для SERVER-режима примените `clinic_laravel7_admin_api_patch.zip`: `POST /tasks` и `PATCH /service-requests/{id}/status` доступны только администратору; проверка выполняется Laravel.


## Диагностика

Во вкладке «Диагностика» доступны проверка API (`GET /health` относительно `API_BASE_URL`), проверка авторизации (`GET /auth/me`), состояние соединения Laravel с БД, объём локально закэшированных данных и время последней успешной синхронизации. Подробные события доступны во вкладке «Отладка».
